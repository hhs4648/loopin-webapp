# 복습하기

하단 탭 `복습노트` → 풀스크린 오버레이. 라우트가 아니라 호출 측의 `reviewOpen` 상태로 연다
(`MainHomeScreen`, `AssignmentReceivedScreen`).

학생이 푼 답안을 **분류별로 묶어** 보여준다 — 단어·문장은 **단원별**, 문법은 **개념별**.
맨 위 「오늘의 맞춤 복습」 파란 카드가 1개를 추천하고, 그 아래는 「단원별」 · 「문법」
두 구역으로 나뉜 전체 목록이다(순위표가 아니라 골라 들어가는 목록).

상단 `<` 뒤로가기(`BackButtonOverlay`)는 설정·학습 화면과 같은 Figma 좌표다.
닫기는 호출 측 `useBackNavigation` / `reviewOpen` 해제가 담당한다.
제목 「복습하기」는 뒤로가기 **바로 아래**(히트 y+h+2px, 너비 기준 %)에 두고,
카드·목록은 그 아래에서 시작한다.

## 이 화면만 Figma 이미지 오버레이를 쓰지 않는다

다른 학습 화면은 `FigmaAssetFrame` 위에 투명 히트영역을 올리지만, 이 화면은 **직접 그린다.**

시안 `review-main.svg`는 글자가 전부 벡터 path로 아웃라인화돼 있어(`<text>` 노드 0개)
`to부정사`·`오답율 38%` 같은 값을 코드로 교체할 수 없다. 이미지 위에 텍스트를 덧그리면
`docs/uiux.md`의 「이미지 위 텍스트 중복 렌더 금지」를 어기게 된다.

그래서 시안에서 **색과 치수만** 옮기고(`review-main.ts`의 `REVIEW_COLORS`),
일러스트 2개는 시안 내장 PNG에서 추출해 쓴다. 4.2MB 시안은 더 이상 로드하지 않는다.

### 「오늘의 맞춤 복습」 카드 좌표의 출처

카드는 별도 시안 **`Rectangle.svg`**(393×292, 카드가 (20,20)에 353×252)를 기준으로 한다.
좌표는 Chrome `getBBox()`로 잰 값을 카드 좌상단 기준으로 옮겨 `REVIEW_CARD`에 넣었다.

| 요소 | 카드 기준 |
|------|----------|
| 카드 | 353×252, radius 24, `#24A0FF` |
| 고양이 흰 원 | 72×72, top 8, 오른쪽에서 31 |
| 고양이 이미지 | 84.6×65.2 — 원보다 커서 **밖으로 삐져나온다** (시안 그대로) |
| 상단 라벨 | 「오늘의 맞춤 복습」(분류명 위, 2026-08-10 추가) |
| 구분선 | x16~337, y≈92, h2, 흰색 40% |
| 숫자·라벨 3열 | x 16 / 123 / 230 (안쪽 폭 321을 3등분) |
| 버튼 | x16~337, y182, h48, radius 24, **흰 배경 + `#484848` 글자 + →** |

**글자 크기는 시안 px가 아니라 시안의 잉크(ink) 폭·높이에 맞춘 값이다** (`REVIEW_CARD_FONT`).
이 앱은 `--font-sans`에 `Pretendard`를 적어두고도 **실제로 로드하지 않아**(`@font-face`·CDN 링크 없음)
시스템 폰트로 대체되는데, 대체 폰트가 Pretendard보다 넓어서 시안 px를 그대로 쓰면 글자가 커 보인다.
세로 위치도 요소 상단이 아니라 **잉크 상단**이 시안과 맞도록 잡았다 (오차 0.6px 이내).

> Pretendard를 실제로 로드하게 되면 `REVIEW_CARD_FONT`와 `REVIEW_CARD`의 `*Top` 값을
> 시안 원래 수치로 되돌려야 한다.

## 분류 체계 (2026-08-07 변경)

교사가 고르는 출제 형식(짝맞추기 · 3지선다 · 영작 …)은 쓰지 않는다.

| 분류 | 기준 | 예 |
|------|------|-----|
| 단어 | **단원별** | `5단원 단어` |
| 문장 | **단원별** | `5단원 문장` |
| 문법 | **개념별**(`grammar[].major`) | `관계대명사`, `to부정사` |

**단어·문장이 단원 기준인 이유** — 내신 시험 범위가 단원 단위라 학생이 복습에 들어오는 동기와
맞고("다음 주 3단원 시험"), 한 단원이 곧 한 세션 분량이 된다. 교사가 한 단원을 파트로 쪼개
여러 과제로 내도(교사측 `problem-sets.ts`) 학생 쪽에서 다시 하나로 합쳐진다.

> 처음(2026-08-06)에는 능력 기준(뜻/듣기/쓰임/어순/영작)으로 묶었다. 약점 진단에는 그쪽이
> 낫지만, 한 분류에 학기 전체 문항이 다 들어와 세션이 성립하지 않았다. 능력별 약점은
> 나중에 단원 안 드릴다운으로 살린다.

**문법만 단원이 아닌 이유** — 문법 개념은 단원을 넘나들며 반복돼서 단원에 가두면 약점이
안 보인다. 개념당 8문항 정도 출제하므로 분류 하나가 너무 작아지지도 않는다.
개념은 교사측 `content-snapshot.ts`가 문제은행 `major`/`minor`를 실어 보낸다.
**2026-08 이전 스냅샷에는 `major`가 없다** — 그런 문항은 「문법」 하나로 묶인다
(`GRAMMAR_FALLBACK_LABEL`).

### 집계 키는 단원 문자열이 아니라 `학년 + 교과서 + 단원`

`reviewCategoryKey`. 단원만으로 묶으면 교사가 한 반에 교과서와 부교재를 섞어 냈을 때 서로 다른
교재의 5단원이 한 칸에 합쳐져 **복습에 남의 교재 단어가 섞여 나온다.**
교사측 `problem-sets.ts`도 「학년·교과서·단원이 모두 같아야 한 단원」으로 파트를 묶는다 — 같은 규칙.

라벨은 그래도 `5단원 단어`로 짧게 쓴다. 학생은 보통 교과서 하나만 쓰기 때문이다.
**같은 라벨이 둘 이상 생길 때만** 교재명을(그래도 겹치면 학년까지) 앞에 붙인다
(`buildReviewLabels`) → `YBM(송) 5단원 단어`.

### 분류 판별을 id 접두어로 하지 않는 이유

`answers` 테이블에 분류 컬럼이 없어 `question_id`로 역추적해야 한다. 그런데 접두어
(`word-` / `sent-` / `gram-`)로 갈라서는 안 된다 — 직접 출제(custom draft)는 `custom-s-0`처럼
다른 접두어를 쓴다. 반드시 **과제 스냅샷의 배열을 조회**해서 단어/문장/문법을 가린다
(`resolveReviewCategory`). 판별되지 않는 문항은 집계에서 **뺀다** — 아무 분류에나 넣느니 빼는 게 낫다.

단원도 마찬가지로 id에 박힌 문자열(`word-중3-YBM(송)-5단원-1`)이 아니라 **스냅샷의 `unit` 필드**에서
가져온다. 직접 출제 문항 id에는 단원이 없다. `unit`이 비면 `기타`로 모인다.

## 집계 규칙

`features/review/review-stats.ts`

- 기간 제한 없이 **전체 기록**.
- 같은 문항을 여러 번 풀었으면 **가장 최근 답안만** 센다 → 다시 맞히면 오답 풀에서 빠진다.
- `is_correct`가 `null`인 답안(미채점)은 정답으로도 오답으로도 세지 않는다.
- 표본이 **3문항 미만**(`MIN_ANSWERED_FOR_REVIEW`)인 분류는 제외 — 1문제 틀리고 오답률 100%가 되는 것 방지.
- 오답이 0인 분류는 제외.
- **개수 상한**: 단원별·문법 각각 **최대 2개** (`MAX_UNIT_REVIEW_TYPES` / `MAX_GRAMMAR_REVIEW_TYPES`).
- 정렬: 단원별·문법 모두 **오답률 내림차순** (동률이면 오답 수 ↓, 그다음 라벨).

### 복습 세션은 오답만이 아니라 분류 전체를 푼다

그래서 카드의 「복습 문제」·「예상 시간」은 오답 수가 아니라 **분류 전체 문항 수**(`questionTotal`)로 낸다.
이 수는 답안이 아니라 스냅샷에서 센다 — 아직 한 번도 안 푼 문항도 복습 대상이기 때문이다
(`collectPools` → `buildAssignmentSections` + `listSectionQuestionIds`).
같은 문항 id가 여러 과제에 겹쳐 나오면 한 번만 센다(답안 쪽도 id로 합치므로).

문항 수 상한은 두지 않았다 — 단원 하나가 상한에 걸릴 만큼 커지지 않는다는 판단.

### 복습 과제는 서버에 없는 **합성** 과제다 (`review:` 접두어)

`buildReviewSession`이 만든 `StudentAssignment`는 `assignmentId`가 `review:<분류키>`이고
**`class_assignments`에 존재하지 않는다.** 러너가 스냅샷 하나만 받기 때문에 여러 과제 내용을
합쳐 가짜 과제 한 개로 넘기는 구조다.

그래서 **「서버 과제 목록에 있는가」로 판단하는 코드는 전부 이 접두어를 먼저 걸러야 한다.**
`isReviewAssignmentId()`(`build-review-session.ts`)를 쓴다 — 문자열 비교를 여기저기 복사하다가
한 곳을 빠뜨린 게 실제 버그였다.

> **2026-08-09 버그.** 「교사가 과제를 삭제하면 러너에서 내보낸다」는 가드
> (`MainHomeScreen`의 `serverAssignments` 감시 effect)가 복습 합성 과제를 삭제된 과제로 오인했다.
> `activeAssignment`가 effect의 의존성이라, 「지금 시작하기」로 러너에 들어가는 **그 즉시**
> 다시 돌아 맵으로 튕겼다 — 화면상으로는 버튼을 눌러도 아무 일도 안 일어나는 것처럼 보였다.

접두어를 걸러야 하는 자리(현재):

| 자리 | 왜 |
|------|-----|
| 삭제된 과제 가드 (`serverAssignments` effect) | 목록에 없는 게 정상이라 제외 — 위 버그 |
| `saveCastleRetrySession` | 새로고침 복원 대상이 아님(합성본이 사라지면 복원할 게 없다) |
| 러너 `practiceOnly` | attempt를 열지 않는다 — 서버 FK에 없는 id라 열 수도 없고, 과제 점수에 섞이면 안 된다 |
| 러너 `onlyQuestionIds` 재필터 | 합성본은 이미 분류 문항만 담겨 있어 한 번 더 거르면 0문항이 된다 |
| 완료·나가기 처리 | 맵이 아니라 복습 탭으로 돌려보낸다 |

### 추천 1개를 고르는 법

오답률만 보면 8문항짜리 문법 개념이 3개만 틀려도 37%가 나와 50문항짜리 단원(42%)을 이겨버린다.
분모에 `RECOMMEND_PRIOR = 10`을 더해 표본이 작은 분류를 끌어내린 뒤 고른다(`pickRecommended`).
10은 실측 근거가 없는 조정값이다.

추천된 분류는 **아래 목록에서 빼지 않는다** — 목록이 순위표가 아니라 골라 들어가는 목록이라,
추천된 단원만 빠지면 단원 번호 사이에 구멍이 생겨 오히려 헷갈린다.

### 계산 근거가 없어 임시로 고정한 값

| 표시 | 계산 |
|------|------|
| 예상 시간 | 분류 전체 문항의 형식별 초 합계(`SECONDS_BY_SUFFIX`), 최소 1분 |
| 목표 정확도 | 고정 80% (`TARGET_ACCURACY_PERCENT`) — 학생별로 정할 근거가 아직 없음 |

`SECONDS_BY_SUFFIX`는 **측정값이 아니라 추정치다**(짝맞추기 8초 … 영작 40초). 응답 시간을
저장하고 있지 않다. 형식 무관 고정값(옛 40초)보다는 낫다 — 짝맞추기 50문항과 영작 50문항을
같은 시간으로 표시하면 몇 배씩 틀린다. 응답 시간을 기록하게 되면 실측으로 갈아끼운다.

## 스트릭 — 「연속 복습」이 아니라 「연속 학습」

`features/review/review-streak.ts` · `use-study-streak.ts` · `components/review/StudyStreakPill.tsx`

`🔥 3일 연속 학습 중` 알약. **학원/학교 메인**(`AssignmentReceivedScreen`)과 **복습하기**가
같이 쓴다. 화면마다 따로 계산하면 조회 범위가 조금만 달라도 같은 학생에게 다른 숫자가
보이므로 `useStudyStreak` 하나로 묶었다.

**문구가 「복습」이 아닌 이유**: 복습 풀이는 연습 모드라 「복습한 날」서버 기록이 없다.
지금 셀 수 있는 건 **과제를 푼 날**뿐이다. 복습을 한 번도 안 한 학생에게 "5일 연속 복습 중"을
띄우면 거짓말이 된다. `review_sessions`가 생기면 `computeStudyStreak`에 복습 기록 시각을 같이
넘겨 진짜 복습 스트릭으로 승격시킨다.

### 데이터는 `attempts` 한 방 조회 (`fetchStudyTimestamps`)

`fetchReviewAnswers`(3연쇄 조회 · 최대 5000행)를 쓰지 않는다. 메인은 앱을 켜면 바로 뜨는
화면이라 조회 비용이 곧 체감 속도고, **혼자 공부 메인은 반이 없을 수도 있다.**
"공부를 했는가"는 어느 반이냐와 무관하므로 `attempts`를 학생 기준으로 바로 훑는다 —
반 스코프가 없어져서 두 메인이 같은 코드로 돌아간다.

`started_at`과 `updated_at`을 **둘 다** 센다. `started_at`만 보면 어제 시작한 과제를 오늘 이어서
풀었을 때 오늘이 빠진다. **알려진 한계**: `updated_at`은 마지막 수정 시각 하나뿐이라 사흘에 걸쳐
이어 푼 과제의 *중간 날*은 복원되지 않는다. 답안별 시각을 봐야 정확해지는데 그건 조회가 3배가
된다 — 살아 있는 스트릭 판정에는 마지막 활동일로 충분하다고 보고 감수한 것이다.

### 계산 규칙

- **날짜 경계는 KST 고정.** 서버 시각이 UTC라 밤 11시 학습을 UTC 날짜로 묶으면 전날로 밀려
  스트릭이 하루씩 어긋난다. 기기 시간대를 쓰지 않는 건 시계가 틀어진 기기에서 흔들리지 않게 하려고.
- **오늘 안 풀었어도 어제까지 이어졌으면 살아 있다.** 하루가 시작되자마자 0으로 떨어지면
  "오늘도 이어가요"라고 말할 대상이 사라진다. 이틀이 비면 끊긴다.
- **2일부터 표시**(`MIN_STREAK_DAYS_TO_SHOW`) — 「1일 연속」은 어색하다.
- 조회는 최근 **60일**(`STREAK_LOOKBACK_DAYS`)까지만.
- 복습할 게 없는 날에도 띄운다 — 습관에 대한 칭찬이라 목록 유무와 무관하다.

### 배치는 반드시 absolute

스트릭은 본문과 별도 조회라 늦게 도착할 수 있다. 흐름(flow)에 넣으면 도착하는 순간 아래 내용이
밀린다. 세 화면 모두 absolute로 띄우고, 복습하기는 제목과 **같은 줄 오른쪽**에 두되 줄에
`min-h`를 줘서 나타나도 아무것도 움직이지 않게 했다.

## 연속 학습 축하 화면 (2026-08-09)

`components/streak-celebration/` — `StreakCelebrationScreen.tsx` + `streak-celebration.ts`

듀오링고식 전체 화면 축하. 과제를 끝내고 **종합 완료 화면으로 가는 길목에 한 장 끼운다**
(`MainHomeScreen`의 러너 `onCompleted` → `resolveStreakCelebration()` → 있으면 축하 먼저,
닫으면 `openCompletedCastle`). 점수를 먼저 보여주면 이미 끝난 기분이라 축하가 늦다.

**메인 맵의 별 배지가 날아와 앉은 뒤, 별 안 숫자가 어제 값에서 오늘 값으로 바뀐다.**
착지 링이 퍼지고 색종이가 떨어지며 주간 7칸이 올라오고, 오늘 칸은 숫자가 바뀌는 순간에 맞춰
톡 찍힌다. 화면 전체가 버튼이고 탭하면 완료 화면으로 넘어간다.

새 그림을 만들지 않고 **메인 맵의 그 배지**(`StudyStreakBadgeArt`)를 그대로 크게 쓴다.
같은 물건이 커져서 날아온 것으로 읽혀야 「내 스트릭이 자랐다」가 전달된다 — 축하 화면 전용
그래픽을 따로 두면 메인의 배지와 남남이 된다. 그래서 배지 안쪽 글자 좌표(별 안 숫자·구름
문구)를 `StudyStreakBadgeArt` 한 곳에 모으고 `StudyStreakBadge`(메인)와 축하 화면이 공유한다.
**한쪽에 복사해 두면 한쪽만 고쳐져 어긋난다.**

**숫자는 0부터 세지 않는다.** `N-1 → N`으로 바꾼다 — 0부터 세면 오늘 처음 시작한 것처럼
보이고, 「이어왔다」는 느낌이 사라진다. 1일차는 에셋이 웃는 얼굴(`streak-badge-day1.svg`)이라
바꿀 숫자가 없어 날아오기만 한다.

타이밍 상수는 `streak-celebration.ts`에 모여 있고 서로 물려 있다
(`STREAK_BADGE_LAND_MS` → `STREAK_NUMBER_CHANGE_MS` → `STREAK_TAP_BLOCK_MS`).
`index.css`의 `streak-badge-fly-in` 길이도 `STREAK_BADGE_LAND_MS`와 같아야 한다.

**하루 한 번만 뜬다.** `localStorage`(`loopin-streak-celebrated-day`)에 마지막으로 띄운 KST
날짜를 적어 둔다. 과제 3개 푼 날 세 번 뜨면 축하가 아니라 방해다. 메모리 플래그로 하면
완료 화면에서 새로고침하고 다시 풀 때 또 뜬다. 서버에 둘 값은 아니다 — 기기마다 한 번이면 충분하고
이것 때문에 컬럼을 늘릴 이유가 없다.

| 규칙 | 값 | 왜 |
|------|-----|-----|
| 발동 | 과제 완료(`practiceOnly` 제외) | 「틀린문제만」 연습은 attempt를 안 열어 학습일로 세지 않는다 |
| 최소 일수 | **1일부터** | 상단 알약은 2일부터지만(`MIN_STREAK_DAYS_TO_SHOW`) 스트릭이 *시작되는* 순간이 이어가게 만드는 순간이다 |
| 조회 실패 시 | 조용히 건너뜀 | `fetchStudyTimestamps`가 `[]`를 주면 `includesToday`가 false라 축하하지 않는다. **이때 「오늘 띄움」 기록도 남기지 않아** 다음 과제에서 다시 시도한다 |
| 탭 잠금 | `STREAK_TAP_BLOCK_MS`(700ms) | 완료 CTA 연타가 관통해 축하가 즉시 사라지는 것 방지 |
| 움직임 줄이기 | `prefers-reduced-motion`에서 애니메이션 전부 정지 | 일수·주간 현황이 정보 본체라 정지 상태로도 그대로 읽힌다 |

**복습 완료는 아직 축하에 안 붙인다.** 복습은 연습 모드라 attempt를 안 열고,
`review_sessions`도 없어 「복습을 끝냈다」는 서버 이벤트가 없다.
테이블이 생기면 완료 지점에서 `resolveStreakCelebration()`을 같은 방식으로 부르면 된다.

**주간 띠는 연속 일수와 다른 것을 본다.** 연속은 주 경계를 넘어 이어지지만 띠는 이번 주(월~일)만
보여준다. 「3일 연속」인데 띠에 2칸만 찍혀 있을 수 있다(월요일에 걸친 경우) — 버그가 아니다.

**새 에셋은 0개다.** 배지는 메인이 이미 쓰는 `streak-badge.svg` / `streak-badge-day1.svg`이고,
색종이·착지 링·주간 칸은 전부 DOM/인라인 SVG다. 배지 안에 「N일 연속 학습 중」 글자가 이미
들어 있으므로 **큰 숫자를 따로 두지 않는다** — 두면 같은 말이 두 번 나온다.

## 데이터 조회

`lib/sync/review-api.ts`의 `fetchReviewAnswers(classId)` —
`class_assignments`(스냅샷) → 내 `attempts` → `answers` 3단 조회.

`answers` 정렬은 **최신순**이어야 한다(`ANSWER_FETCH_LIMIT = 5000`). 상한에 걸렸을 때 잘려나가는
쪽이 오래된 답안이 되도록 — 오름차순이면 최근 기록이 날아가 「가장 최근 답안만 센다」는 집계
전제가 조용히 깨진다.

스트릭은 이 조회를 쓰지 않는다 — 위 「스트릭」 절의 `fetchStudyTimestamps` 참고.

기존 `fetchWrongQuestionIds`는 attempt 하나 단위라 유형별 집계에 쓸 수 없다.
동기화가 꺼져 있거나 조회에 실패하면 빈 배열을 돌려주고 화면은 빈 상태를 보여준다.

## 복습 세션 시작 (2026-08-09)

「지금 시작하기」·목록 카드 탭 → `buildReviewSession`이 반 과제 스냅샷에서
해당 분류(단원 단어/문장 · 문법 개념) 콘텐츠를 **전부** 합성한 뒤,
합성본에서 출제되는 문항 전체를 `AssignmentRunnerScreen` 연습 모드로 넘긴다.
오답만이 아니라 카드의 「복습 문제」 수와 같은 범위를 다시 푼다.

- 학원/학교 메인: `MainHomeScreen.startReviewSession` → `assignment-runner` step
- 직접 출제 id 충돌(`custom-s-0` 등): 내용이 다르면 나중 문항은 제외, 같으면 재사용
- `fetchReviewAnswers`는 답안과 함께 반 **전체** 과제 스냅샷을 돌려준다

### 복습 완료 후 카드 갱신 (2026-08-09)

복습은 연습 모드라 서버 `answers`에 안 남지만, 완료 시 로컬에 결과를 남겨 카드를 다시 배치한다
(`persist-review-outcome.ts`).

| 결과 | 동작 |
|------|------|
| **만점** | `loopin-review-cleared-at`에 완료 시각 → 목록·추천에서 감춤. 과제에서 다시 틀리면(`lastWrongAt > reviewedAt`) 복귀 |
| **오답 있음** | 출제 문항 전부의 정오를 `loopin-review-practice-answers`에 저장 → `summarizeReviewTypes`가 문항별 **최신** 답안만 쓰므로 오답률·추천 카드·문법 목록 순서가 갱신됨. 만점 감추기가 있으면 푼다 |

- `ReviewMainWindow`는 서버 답안 + 로컬 연습 답안을 합친 뒤 집계한다.
- 서버 `review_sessions` / `review_answers`가 생기면 localStorage 자리를 그쪽으로 옮긴다.
